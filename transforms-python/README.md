# transforms-python — EnLiST pipeline source

This subproject holds all Python source for the EnLiST pipeline. See the
[repository README](../README.md) for what the pipeline does, the stage-by-stage
architecture, and the expected input schema.

## Layout

```
src/myproject/
├── config.py                   # all environment-specific values (placeholders in this release)
├── llm.py                      # model wrapper: completion call, token usage, cost accounting
├── notation.py                 # EnLiST line-of-therapy adjudicator (deterministic)
├── nw_align.py                 # Needleman-Wunsch alignment + field accuracy (deterministic)
├── note_cleaning.py            # boilerplate stripper (deterministic)
├── text_sections.py            # section-header extraction (deterministic)
├── pipeline.py                 # Foundry transform discovery
├── prompts/
│   └── enlist_prompts.py       # agent prompts and guideline text
└── datasets/                   # one module per pipeline stage
    ├── stage1_note_prep.py
    ├── stage2_imaging_classifier.py
    ├── stage3_agent_extraction.py
    ├── stage3_terra.py         # model A/B variant of stage 3
    ├── stage3c_patient_summary.py
    ├── stage4_eval_vs_gs.py
    └── stage4_terra.py         # model A/B variant of stage 4
```

`datasets/` modules are Foundry transform wiring. The domain logic lives in the
deterministic modules and in `prompts/`.

## Configuration

Dataset identifiers and output paths in `config.py` are non-functional placeholders.
Replace them with identifiers from your own Foundry instance before running. Constants
marked `RESERVED` or `DIAGNOSTIC` are retained deliberately and are not read by any
transform in this release.

## Tests

The unit tests were removed from this public release. To add tests, apply the
`com.palantir.transforms.lang.pytest-defaults` Gradle plugin in `build.gradle` — it is
present but commented out — and place tests under `src/test/`.

## Notes on the build

This is a Foundry transforms project and resolves its dependencies against Foundry
infrastructure. It does not build standalone. The conda lockfiles are autogenerated and
should not be edited by hand; regenerate them with `./gradlew --write-locks` in an
environment that can reach the artifact repository.
